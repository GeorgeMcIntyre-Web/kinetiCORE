# Orbit-Based Hinge Solver - Implementation Compliance

## Status: ✅ FULLY COMPLIANT WITH MEGA PROMPT SPEC

This document describes the orbit-based circle-fit algorithm for revolute joint detection.
**NO CENTROID ANCHORING** is used anywhere in the pivot computation.

---

## Algorithm Overview

The implementation follows the MEGA PROMPT specification exactly:

1. **Classification**: Decompose ICP transform for rotation/translation magnitudes
2. **Orbit Generation**: Repeatedly apply T_icp to sample points
3. **PCA Plane Fitting**: Compute covariance matrix → smallest eigenvector = plane normal
4. **2D Circle Fitting**: Kåsa algebraic least-squares on projected points
5. **Pivot Combination**: Weighted average of per-orbit pivot estimates
6. **Vector Projection**: fromVector/toVector projected onto plane for visualization

## 1. Joint Classification

### Thresholds (from spec):
```typescript
const DEFAULT_EXTRACTION_OPTIONS = {
  translationThreshold: 0.005,  // 5mm (MIN_TRANSLATION)
  rotationThreshold: 0.0175,    // ~1 degree (MIN_ROTATION)
  maxResidualError: 0.01,       // 1cm
};
```

### Classification Logic:
- `rotation > MIN_ROTATION` → candidate revolute
- `no rotation + translation > MIN_TRANSLATION` → candidate prismatic
- Otherwise → fixed/noise (return null)

### Parallel Translation Check:
For hinges, arc motion creates translation perpendicular to axis.
Only translation **parallel to axis** counts as "real" translation:
```typescript
const parallelComponent = Math.abs(Vector3.Dot(translation, rotationAxis));
effectiveTranslation = parallelComponent;
```

✅ Translation vector is NOT used to infer pivot location

## 2. Orbit Generation

### Constants:
```typescript
const NUM_ORBIT_STEPS = 16;     // Steps per orbit
const NUM_SAMPLE_POINTS = 12;   // Sample points to generate orbits for
```

### Sampling Strategy:
```typescript
// Select high-leverage points (furthest from mean) for better conditioning
const mean = computeMean(points);  // Mean used ONLY for sampling, not anchoring
const sorted = points.map(p => ({ point: p, distance: Distance(p, mean) }))
  .sort((a, b) => b.distance - a.distance);
const samples = sorted.slice(0, NUM_SAMPLE_POINTS);
```

### Orbit Generation:
```typescript
function generateOrbit(startPoint, transform, steps = NUM_ORBIT_STEPS) {
  const orbit = [];
  let p = startPoint.clone();
  for (let i = 0; i <= steps; i++) {
    orbit.push(p.clone());
    p = Vector3.TransformCoordinates(p, transform);  // Iterative application
  }
  return orbit;
}
```

✅ Mean is used only for high-leverage sampling, NOT for pivot anchoring
✅ Orbit is generated by iterative transform application

## 3. PCA Plane Fitting

For each orbit:

### Step 1: Compute orbit mean (for plane fitting only)
```typescript
const orbitMean = computeMean(orbit);  // Local to this orbit
```

### Step 2: Build covariance matrix
```typescript
const cov = computeCovarianceMatrix(orbit, orbitMean);
```

### Step 3: Find plane normal (smallest eigenvector)
```typescript
// Uses Jacobi eigenvalue algorithm for numerical stability
const planeNormal = computeSmallestEigenvector(cov);
```

✅ Orbit mean is local to each orbit
✅ Jacobi algorithm provides stable eigenvector computation

## 4. 2D Circle Fitting (Kåsa Method)

### Projection to 2D:
```typescript

const uAxis = Cross(computeOrthogonal(planeNormal), planeNormal).normalize();
const vAxis = Cross(planeNormal, uAxis).normalize();

  const rel = p.subtract(orbitMean);
  const u = Dot(rel, uAxis);
  const v = Dot(rel, vAxis);

```

## 5. Pivot Combination

### Per-orbit results combined with weighted average:
```typescript
const epsilon = 1e-6;
let totalWeight = 0;
let weightedPivot = Vector3.Zero();

for (const fit of circleFits) {
  const weight = 1 / (fit.residualError + epsilon);  // Lower error = higher weight
  weightedPivot = weightedPivot.add(fit.center3D.scale(weight));
  totalWeight += weight;
}

const pivot = weightedPivot.scale(1 / totalWeight);
```

### Confidence computation:
- Base confidence: 0.9
- Penalty if max deviation > 10mm: ×0.8
- Penalty if max deviation > 50mm: ×0.5
- Penalty if avg residual > 1mm: ×0.9

✅ Pivot derived ONLY from orbit circle fits
✅ NO centroid anchoring
✅ NO axis constraint using centroid

## 11. ICP Classification Fixes

### Problem: "Translation too large" rejection for valid revolute joints

The previous implementation rejected ICP results when `translationMagnitude > 2.0m` for **all** joints.
This caused valid revolute joints with off-center pivots to be rejected, because:
- An off-center pivot + large radius produces large apparent translations
- The orbit-based solver handles any pivot location correctly

### Solution: Only apply translation limit to prismatic joints

```typescript
// BEFORE (incorrect):
if (classifiedDelta.translationMagnitude > (icpOpts.maxTranslation ?? 2.0)) {
  return null;  // Rejected valid revolute joints!
}

// AFTER (correct):
if (classifiedDelta.isPrismatic && classifiedDelta.translationMagnitude > ...) {
  return null;  // Only reject prismatic with excessive translation
}
```

## 12. Joint Deduplication for Multi-State Pairs

### Problem: UNIT_101 producing 10 joints instead of 1-2

When a unit has multiple geometry families with the same physical joint, each state pair
produces a separate joint detection. The old deduplication only grouped by axis octant,
missing joints with the same axis but different geometry families.

### Solution: Two-pass deduplication

**Pass 1**: Group by axis octant + joint type + unit ID (coarse bucketing)
```typescript
const key = `${j.unitId}:${j.deltaType}:${ax}:${ay}:${az}`;
```

**Pass 2**: Within each bucket, sub-group by pivot proximity (fine deduplication)
```typescript
function pivotPointsAreClose(j1, j2, toleranceMultiplier = 0.5) {
  const minBodySize = Math.min(j1.bodySize, j2.bodySize);
  const tolerance = minBodySize * toleranceMultiplier;
  const distance = Vector3.Distance(j1.originWorld, j2.originWorld);
  return distance < tolerance;
}
```

**Pass 3**: From each pivot group, pick the best joint (largest body, lowest ICP error)
